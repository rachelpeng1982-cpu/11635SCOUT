# 活動維運／故障復原 SOP

## 開場

- 主辦確認日期、人數、雨備、場地及通關政策。場地不明不得開站。
- 系統管理員檢查備份、Google配額、試算表分享、白名單、PIN、部署版本、Forms trigger與失敗紀錄。
- 每站確認核准耗時／線數，關主回報個人排隊與小隊排隊；組長看30站狀態、更新時間及高風險告警。
- 工作人員只在自己裝置登入核准帳號；共用裝置結束操作要登出Google。個人通行證需用頁面登出清除session。

## 正常核章

1. 關主辨識工作人員、選本站、輸入PIN。
2. 掃描個人QR或手動輸入編號並另核對本人；查詢預覽姓名及本站是否已完成。
3. 個人模式確認本人；小隊模式逐一勾選實到者，核對實到／未到，勾確認，再二次確認送出。預設所有成員都不勾選。
4. 只以伺服器確認為完成。重複則不得另換ID或修改表格繞過。
5. 即時更新排隊人數／隊數；高風險可建立內部告警，勿輸入不必要醫療個資。組長派工、結案或發安全公告。

## 逾時、斷線、回應遺失

- 畫面顯示「未確認成功」不等於未寫入。保留原畫面，用同對象的原請求重試；前端保留冪等鍵，伺服器回傳前次已承諾結果。
- 若頁面已關閉，先重新查詢該人／站與本站歷程，再由系統管理員對帳。不可假裝離線核章已成功。
- 小隊核章是單一原子 batchUpdate；失敗不得逐人另造補章。先檢查 StampBatches、Requests、StampLogs、AuditLogs 是否同批齊備，再決定重試或補償。
- 維持紙本備援：時間、站號、公開學員編號、實到成員、關主、事件原因；不抄QR/PIN/電話。紙本不是即時有效章，事後由授權管理員在系統確認後補登並留原因；目前無批量紙本自動匯入工具。

## 更正

由系統管理員依公開學員編號、站號與本站歷程logId核對，在管理畫面輸入理由執行撤銷。保留原PASS及REVOKED補償事件；三類統計自動重算。活動組長不能直接刪改成績，需走更正申請與管理員執行流程。

## 備份與還原演練

1. 活動前、重大設定前、活動後由資料擁有人將試算表複製到受限備份資料夾；記錄UTC時間、部署版本、總列數、有效章總數、Requests總數及雜湊核對方式。包含所有十一張表，不只StampLogs。
2. SECRET 與權限相關 Script Properties 由核准維運者另存於主辦受控秘密管理位置，不能寫入一般備份CSV或專案ZIP。Forms原始回覆另行受控備份。
3. 還原時暫停兩個版本的寫入，複製備份到隔離新表、以測試專案設定SPREADSHEET_ID。先驗證表頭、11表關聯、有效章、批次實到／缺席、Requests與稽核。
4. 切換或還原時**換新 SECRET** 並私密重發QR／PIN，使舊session與QR不可用，避免備份較舊的hash讓已撤銷憑證復活。工作人員重新解鎖；不要把舊明碼憑證併回。
5. 與備份時間後的受控紙本／對帳紀錄逐筆核對，必要時由管理員補償更正。關主及組長確認後才恢復服務。
6. 實際還原演練未執行；需記錄恢復耗時、可接受資料缺口、演練人及簽核。

## 容量與告警

公開站況快取10秒；頁面20秒輪詢、失敗指數退避至120秒，背景頁120秒。關主提交與管理資料讀取仍會競爭ScriptLock。單表15,000資料列上限，API逾時30秒、鎖等待10秒；上限是保護，不是已驗證吞吐量。密切監控執行時間／配額、BUSY_RETRY、CAPACITY_LIMIT及最後同步時間。高負載先降低非必要輪詢並依安全程序暫停核章，不能刪Requests或AuditLogs騰空間。

## 收尾

關站、撤銷工作人員權限、停止trigger、依主辦留存期限封存並刪除不必要個資。交接資料與Google資源歸屬；QR與快取不作公開成果。成果報表標明統計口徑及Asia/Taipei時間範圍。預算／物資可另以受控表單記錄項目、數量、單價、核准人與實支，不能把未核定67,100元當實支。
