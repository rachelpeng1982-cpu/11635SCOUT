# IMPLEMENTATION_PLAN（暫定）

狀態：僅為依現有附件建立的候選工作順序，不替代缺失 NORTH_STAR.md 的 Phase 定義。取得四份指定文件後須逐條對照修訂，才開始依正式 Phase 實作。

## 候選 Phase 0：規格與基線

- 完整讀取四份指定文件；建立需求、原始規格章節、程式與驗收測試的對照。
- 保存原始 HTML，將示範姓名、進度、安全碼、站況與正式資料分離。
- 確認人數、15 站門檻是否成立、30 站名稱、現勘位置、Google 部署與授權方式。
- 通過條件：缺失規格齊備，正式 Phase 及資料來源可追溯。

## 候選 Phase 1：資料模型、權限、安全與測試

- 候選模型：Participants、Teams、Stations、StampLogs、StationStatus、StaffPermissions、AuditLogs、Alerts。最終表名及拆分依 NORTH_STAR.md，不能假定此清單為正式規格。
- 使用穩定 participant_id 作關聯；QR 憑證可撤銷／輪替，不作公開主鍵；進度從有效核章重建。
- 定義個人組完成數、小隊完成隊數、小隊成員完成數；確認隊伍成員異動對統計的影響。
- 設計伺服器驗證身分及站點範圍；PIN 不作唯一授權；區長、組長、管理員權限按正式規格劃定。
- 個人資料最小化；預設不允許查閱其他參加者，公開站況不含名冊、緊急聯絡人及憑證。
- 測試：無憑證、過期、撤銷、跨站越權、非組長查總表、重複核章、請求重送、實到成員白名單、錯誤輸入與批次失敗。
- 通過條件：模型、API 契約與安全測試先完成，未授權操作不得產生寫入。

## 候選 Phase 2：Google 服務與核章後端

- Forms 欄位映射與可重送的匯入流程；不以姓名自動合併人員。
- Sheets 建表、驗證、匯入預檢、版本遷移與環境隔離；種子匯入不覆寫正式核章。
- Apps Script 所有寫入以伺服器權限檢查；以鎖保護查重／寫入，設請求識別與結果查詢。
- 小隊核章以實到成員建立逐人記錄及 batch_id；定義整批衝突處理、提交狀態與失敗恢復，避免部分結果進入統計。
- 更正須有理由與稽核，不無痕刪除核章。
- 通過條件：沙盒 Google 服務整合、並行重複、提交中斷、重送及重建統計測試通過。

## 候選 Phase 3：四大介面整合

- 沿用既有森林、羊皮紙、羅盤金與徽章視覺；修復遺失資源及導航。
- 通行證顯示個人真實進度與可驗證 QR；小隊資料可見範圍依正式權限。
- 地圖使用核准的 30 站與位置，維持非疏散圖警語，不虛構距離或座標。
- 關主確認實到成員、核章結果與錯誤；離線不得宣稱已成功核章。
- 戰情中心依正式同步間隔更新，顯示最後成功時間、過期／失敗狀態、分類統計及受權限保護的匯出。
- 通過條件：手機與桌機操作、鍵盤、觸控目標、空資料、斷線及跨頁一致性驗證通過。

## 候選 Phase 4：驗收與部署準備

- 正式與測試資料隔離；預設無示範名冊或偽造即時數據。
- 按正式規模測量 Apps Script 配額、鎖競爭與輪詢負載。
- 完成權限實測、備份還原、資料保留、關主訓練及現場演練。
- 交付驗收紀錄，逐項列出通過／未通過／未測與證據。所有上線條件通過前維持「未通過上線驗收」。
